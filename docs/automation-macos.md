# macOS 自动运行教程

> 目标：让应用每天在固定时间自动发送，不需要一直开着窗口。
>
> 适用版本：macOS 13 及以上（Intel / Apple 芯片均可）。

## 1. 把应用装到固定位置

1. 下载 macOS 版安装包（`.dmg`），双击打开。
2. 把 **Douyin Fire** 拖进「应用程序」文件夹。
3. 第一次打开如果提示"无法验证开发者"或"已损坏"：
   打开「系统设置 → 隐私与安全性」，在页面底部找到被拦截的提示，点「仍要打开」；
   或者右键点击应用图标，选择「打开」。
4. **不要**直接从 `.dmg` 里运行，也不要在「下载」文件夹里设好时间再把应用拖走。

应用真正的数据不在应用包内，而在：

```
~/Library/Application Support/Douyin Fire/
```

移动或重装应用不会丢数据，但会让计划任务指向旧路径（见第 6 节）。

## 2. 先手动跑通一次

在设时间之前，先确认整条链路是通的：

1. 扫码登录；
2. 「好友管理」确认好友备注名；
3. 「消息管理」保存今天要发的内容；
4. 回首页点「立即发送」，在确认窗口核对好友与消息，等它跑完。

「登录与记录」里看到成功记录，再去做第 3 步。

## 3. 设置每日运行时间

1. 打开「自动任务」，选择小时和分钟；
2. 点「保存时间」；
3. 页面上会显示「今天 / 明天 HH:MM」，说明计划任务已写入。

底层写入的是一个用户级 LaunchAgent：

```
~/Library/LaunchAgents/com.meiyh.douyin-auto-fire.plist
```

它同时包含两个触发条件：

- `StartCalendarInterval`：每天你设定的那个时刻；
- `StartInterval = 1800`：每 30 分钟检查一次，用于睡眠 / 关机后的当天补跑。

## 4. 验证计划任务

```bash
# 看任务是否已加载（能看到 pid 或 last exit status 即可）
launchctl print gui/$(id -u)/com.meiyh.douyin-auto-fire | head -n 20

# 看触发时间与实际执行的命令
plutil -p ~/Library/LaunchAgents/com.meiyh.douyin-auto-fire.plist
```

到点之后，在面板「登录与记录」里应该能看到当天的运行记录。

## 5. 关掉应用还会跑吗？

会。launchd 直接调用应用内置的后台程序，不依赖窗口是否打开。
设好时间后可以退出应用，也可以重启电脑——只要到点时**电脑开机、并且登录的是当前这个用户**。

因为是用户级 LaunchAgent，以下情况到点不会执行：

- 电脑关机、或睡眠中没有被唤醒；
- 停在了登录界面，没有进入桌面；
- 你切换到了另一个 macOS 用户。

## 6. 睡眠、关机与补跑规则

| 情况 | 行为 |
| --- | --- |
| 到点电脑醒着且已登录 | 正常执行 |
| 到点电脑在睡眠 | 唤醒后由 30 分钟检查触发补跑 |
| 到点电脑关机 | 开机并登录后补跑 |
| 当天已经成功跑完 | 后续检查直接跳过，不会重复发 |
| 当天有好友失败 | 下一个 30 分钟检查点只补发失败的好友，已成功的不会重复发 |
| 当天已尝试 3 次仍失败 | 当天不再自动重试，等第二天 |

补跑还要满足一个条件：当前时间已经过了你设定的时刻（`--not-before`）。
如果当天过了设定时间才第一次保存计划任务，今天不会立刻补发，从下一个设定时间开始。

## 7. 移动或更新应用之后

计划任务里记录的是应用包内的绝对路径。下面这些操作会让它失效：

- 把应用从「应用程序」移到别处，或移回「下载」；
- 覆盖安装到另一个目录；
- 卸载后重新安装到不同位置。

修复方式（二选一）：

1. **重新打开一次应用**：启动时会自动把计划任务指向当前位置；
2. 打开「自动任务」，再点一次「保存时间」。

## 8. 日志与排查

| 位置 | 内容 |
| --- | --- |
| 面板「登录与记录」 | 每天的成功 / 失败 / 待核对好友 |
| `~/Library/Application Support/Douyin Fire/artifacts/run.log` | 每次运行的主日志 |
| `.../artifacts/launchd.out.log` | 计划任务的标准输出 |
| `.../artifacts/launchd.err.log` | 计划任务的报错 |
| `.../logs/desktop-backend.log` | 桌面端后台服务日志 |

常见问题：

- **到点没反应**：先确认 `launchctl print` 里任务存在；再看 `launchd.err.log` 是否有路径错误（多半是应用被移动过）。
- **日志里有"登录状态已失效"**：抖音登录过期，重新扫码登录，计划任务不用改。
- **日志里有"要求进行安全验证"**：抖音风控，应用会主动停止，隔一段时间再试，必要时重新登录。
- **好友被标记为"待核对"**：上一条消息结果不确定，为避免重复发送，应用当天不会自动重发，请在面板里手动确认。

## 9. 修改或停止

- **改时间**：在「自动任务」重新选择并「保存时间」即可，旧的触发时间会被覆盖。
- **停止自动运行**：应用内没有"删除计划任务"的按钮，需要用命令行：

  ```bash
  launchctl bootout gui/$(id -u)/com.meiyh.douyin-auto-fire
  rm ~/Library/LaunchAgents/com.meiyh.douyin-auto-fire.plist
  ```

- **卸载应用前**：先执行上面的停止命令，否则系统会不断尝试启动一个已经不存在的程序。

## 10. 需要一台常开的机器？

如果 Mac 经常关机或长时间睡眠，定时任务就会频繁错过。两种更稳的做法：

- 用一台常开的小主机 / 云服务器跑 Linux 版，见 [Linux 自动运行教程](automation-linux.md)；
- 或者保持 Mac 接电源、关闭睡眠（「系统设置 → 锁定屏幕 → 显示器关闭时…」里允许电源小憩），并确认到点时有网络。
