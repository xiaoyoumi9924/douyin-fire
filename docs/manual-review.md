# 待核对结果处理

顶部「待核对处理」按钮已移除。好友状态为「待核对」时，可以在「好友管理」点击该行的「核对结果」。包含不确定结果的运行详情提供「处理今日待核对」入口。

先打开抖音聊天记录，核实对应对象、时间和消息。程序不会代替你判断消息是否真正送达。

- **我确认已发送**：再次确认后，将这一条消息标记为人工确认成功；普通发送和自动任务会跳过它。
- **我确认未发送**：再次确认后保存判断，但仍暂停自动重发。这个操作不会打开浏览器或发消息。
- **只补发这条**：仅对已确认未发送的记录提供，再次确认后只处理这一条消息，不发送同一好友的其他消息，也不联系其他好友。补发结果不明时会重新进入待核对，需要再次人工判断。

不确定时直接关闭即可，原来的防重复保护保留。人工核对记录保存时间和决定，展示在窗口底部的「人工处理记录」中；原始运行记录不被改写。单条补发的新运行记录会标注「单条补发」，不会被当成全天任务全部完成，也不会把成功状态套用到没有尝试的其他消息。

处理只适用于当前账号、当前日期、当前配置能够对应的消息。切换账号、跨天、消息内容变化或记录已被处理后，旧请求会被拒绝；配置已变更、无法对应的旧记录只显示数量，不提供补发入口。正在运行任务或系统任务持有账号锁时，不允许同时核对和补发。

文字显示原消息内容，图片显示文件名，表情显示名称。新随机和轮换消息会保存选中的候选编号，核对时显示具体内容，人工补发沿用原选择。旧随机记录没有候选编号时会明确提示需要核对；这类记录确认未发送后，首次补发才会选择并记录候选。

人工处理信息保存在账号自己的 `history.json` 消息条目内，与结果一次原子写入；macOS/Linux 文件权限为 0600。不把好友姓名或消息内容加入公开运行日志，不自动清空当天发送历史。
