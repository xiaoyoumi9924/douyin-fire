# 待核对结果处理

顶部「待核对处理」按钮已移除。好友状态为「待核对」时，可以在「好友管理」点击该行的「核对结果」。包含不确定结果的运行详情提供「处理今日待核对」入口。

先打开抖音聊天记录，核实对应对象、时间和消息。程序不会代替你判断消息是否真正送达。

- **已发送**：将这一条消息标记为人工确认成功；普通发送和自动任务会跳过它。
- **未发送，补发**：保存未发送的判断，并立即补发当前这一条消息，不再弹出第二次确认。不会发送同一好友的其他消息，也不联系其他好友。
- **立即补发**：已有未发送判断的记录可直接补发。好友已暂停时只保存判断，需要恢复好友后才能补发。结果不明时重新进入待核对，不会自行重复发送。

不确定时直接关闭即可，原来的防重复保护保留。窗口不再展示「人工处理记录」，后台仍保留处理时间和决定；原始运行记录不被改写。单条补发的新运行记录会标注「单条补发」，不会被当成全天任务全部完成，也不会把成功状态套用到没有尝试的其他消息。

处理只适用于当前账号、当前日期、当前配置能够对应的消息。切换账号、跨天、消息内容变化或记录已被处理后，旧请求会被拒绝；配置已变更、无法对应的旧记录只显示数量，不提供补发入口。正在运行任务或系统任务持有账号锁时，不允许同时核对和补发。

文字显示原消息内容，图片显示缩略图，表情显示名称。新随机和轮换消息会保存选中的候选编号，核对时显示具体内容，人工补发沿用原选择。旧随机记录没有候选编号时会明确提示需要核对；这类记录确认未发送后，首次补发才会选择并记录候选。

人工处理信息保存在账号自己的 `history.json` 消息条目内，与结果一次原子写入；macOS/Linux 文件权限为 0600。不把好友姓名或消息内容加入公开运行日志，不自动清空当天发送历史。
