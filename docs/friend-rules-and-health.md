# 好友专属消息与健康检查

## 好友专属消息

在「好友管理」的每行点击「消息规则」。每位好友可以沿用「消息管理」中的默认消息，也可以使用自己的专属文字和图片。

专属发送规则有四种：

- 固定发送一条：只允许一条文字或一张图片。
- 随机选一条：从文字和图片候选中随机选一项。
- 每天轮换一条：按候选顺序逐日轮换，同一天重试使用同一候选；候选顺序改变后轮换按新列表计算。
- 依次发送全部：先按文字输入顺序发送每行文字，再按图片列表顺序发送图片。

设置窗口默认只显示自动续火开关、日常消息来源和节日祝福开关。切换到「为这位好友单独设置」才显示文字、图片与发送方式。节日清单和今日内容按需展开，顶部「待核对处理」入口已移除。

生日祝福已取消，旧配置中的生日和自填年度节日不再触发，保存好友规则时移除旧字段。节日祝福默认开启（所有账户、继承默认消息或专属消息的好友均适用），可单独关闭。暂停的好友始终不会发送。

### 默认节日祝福

预置范围为 2026-11-13 至 2027-11-13。按具体年份匹配日期，农历节日不会将同一个公历月日错误地逐年复用。节日当天只发下表的一条文字祝福，替代日常文字、图片和随机/轮换规则；非节日照常使用日常消息。清明不设「快乐」祝福，清明当天仍按日常规则发送。

当天已有发送尝试后修改开关或消息，仍遵循当天快照，新的配置从次日生效，避免重复发送。

发送确认页会展示今天轮换到的具体消息；随机规则在发送前选定候选并记录编号，失败重试、程序重启后的重试和人工补发都沿用这次选择。新产生的待核对记录也会显示选中的具体消息，旧记录没有候选编号时仍需要对照抖音聊天记录核实。

关闭「自动续火」即暂停。暂停立即生效，普通任务和人工单条补发都会跳过；恢复后仍遵守当天的发送历史，不会清空去重状态。其他好友的规则保持不变。

为了避免当天改文案后重复发送，**今天已有发送尝试或历史记录的好友，消息修改从次日生效**。程序会保留这位好友今天实际使用的消息配置；人工核对和去重仍按原配置进行。今天尚未尝试的好友可以立即使用新内容。这个规则也适用于修改默认消息。

发送确认窗口会按好友显示本次实际使用的消息规则，暂停的好友不进入发送清单。修改备注时会保留专属规则和今天的发送状态；删除好友也会移除对应规则。

旧的 `targets[].messages` 配置继续读取，视为各好友原有的专属消息。不能由当前编辑器无损表达的表情或组合只允许保留原消息、暂停/恢复，或改为沿用默认消息，不会静默改写消息类型与顺序。

配置新增 `friend_rules` 和 `daily_messages` 字段；旧配置无需迁移，未设置规则的普通好友默认继承默认消息。保存配置会与账号运行锁互斥，任务运行期间暂不允许修改。

## 登录与任务健康检查

入口在「登录与记录」。点击「检查登录」时，程序只会使用当前账户的凭证打开私信页检查，不发送消息，也不生成截图和浏览器追踪文件。账号暂未启用时也能检查。

登录状态区分：未配置凭证、尚未验证、本次检查可用、明确要求重新登录、需要安全验证、检查未完成。**文件存在不等于登录有效，网络错误也不等于登录失效。** 换凭证会使之前的检查结果失效，超过一天的结果要求重新检查；这个期限只表示检查的新鲜程度，不预测 Cookie 的真实过期时间。

独立的任务健康面板已从界面移除。「登录与记录」保留登录检查与运行历史，好友发送状态在「好友管理」查看；系统任务设置在「自动任务」查看。后端只读诊断接口保留。

系统任务检查只读取 macOS launchd、Windows 任务计划或 Linux crontab，不自动修改已有系统任务。电脑关机、睡眠和断网仍可能影响实际执行，注册成功不代表未来一定发送成功。

登录检查结果保存在账号的 `artifacts/login-health.json` 中，不含 Cookie 原文；macOS/Linux 权限为 0600。检查结果只绑定当前凭证和账号路径，不能复用于其他账户。
