# 抖音自动续火花：同类调研与功能设计

调研时间：2026 年 11 月 14 日。依据当前工作区实际代码（含未提交的修改）与公开项目说明。项目 README 中的功能是作者声明，本次未安装这些项目，也没有登录抖音、发送消息或更改正在运行的任务。

## 结论

延续现在的本地 Web 控制台和 Python + Playwright 方案。优先级依次为：**历史数据保全与查看 → 今日任务健康和异常提醒 → 好友身份绑定 → 真实火花信息探索 → 体验功能**。本项目已有较完整的消息规则，无需重复开发。

## 当前项目已有能力

- 多账号、按账号隔离配置、扫码/凭证登录、登录状态检查与系统定时。
- 聊天列表同步、同名提示、好友暂停、专属文字和图片、固定/随机/轮换/依次发送。
- 节日祝福，当前内置日期表已核实到 2027 年 11 月 13 日。
- 发送前会话核对、每日去重、失败补跑上限、未知结果人工核对后单条补发。
- 运行记录、截图/trace、macOS 通知、钉钉与 Webhook 的后端能力。

代码依据：`app/contacts.py`、`app/rules.py`、`app/health.py`、`app/review.py`、`app/main.py`、`app/notifier.py`、`ui/server.py`。注意：已具备后端能力不等于界面已经提供完整配置入口；通知需继续核对实际配置体验。

## 现状中需要优先解决的问题

### 1. 合并后的旧历史可能在下次运行时被截断

`app/main.py` 的 `append_run_history` 写入时只保留最后 30 条；`ui/server.py` 的 `run_history` 默认只读取最近 20 条。前次合并的 35 条记录，目前文件已只剩 30 条；是否恰由下次写入截断，本轮没有追溯运行过程。迁移时的原始桌面及网页历史已备份，可用于后续恢复，但备份不等于界面可查。应先解决，不用等新功能。

建议：新记录改为追加写入；页面提供按账号、日期、状态筛选与分页；导入旧历史预览和去重；若将来设清理规则，必须保护待核对记录、当日去重和备份。数据库是否必要由实际数据规模决定，不为此马上重写。

### 2. 好友身份仍有同名和改名边界

`Target` 当前以 `name` 表示好友；同步时尝试读取页面行的 identity，但 `finish_contacts` 输出仅保留名称，同名会要求人工核对。内部记录引入 `target_id` 可以保持项目内关联，但不自动证明抖音对方身份。

建议分阶段：先在测试页面验证会话 ID 是否存在、稳定且能在发送前二次验证；能可靠验证才绑定。不能验证时维持同名阻止发送和人工确认，不能以猜测替代验证。旧配置按预览逐步迁移，不改写原始记录。

### 3. 定时与诊断应体现证据等级

`app/health.py` 有健康问题聚合，`ui/server.py` 有系统任务检查；现有界面是否完整展示这些结果仍需按实际页面逐项核对。设计时分清“配置存在”“系统任务已注册”“到点已触发”“消息已发送”，避免把已安装当成实际执行成功。

当前本机在删除桌面 App 后使用 Web 项目路径运行，网页服务与原定时任务已指向该目录。对实际部署，应单独验证下一次真实触发与历史记录，不因进程存在就认定定时已成功。

### 4. 登录和网页变更需要更明确的恢复路径

目前健康检查能区分失效、安全验证、检查失败；继续沿用这一分层。网络失败不可直接称作凭证失效。对于选择器失配、页面结构变化，展示可操作说明及脱敏诊断，不展示凭证和私信正文。

## 功能设计

### P0：历史记录中心和安全备份

入口：登录与记录 → 运行历史。增加日期范围、账号和状态筛选；分页查看每次运行与各好友结果；展示“已发送 / 确定失败 / 待人工核对”，不把不确定状态渲染成成功。旧记录按时间展示，支持备份导出和预览恢复。

验收：导入 35 条及重复记录后再追加 1 次，旧记录仍可查；分页数量准确；中断写入不破坏旧文件；导出默认不包含 Cookie、Storage State 或敏感聊天内容；多账号不混淆。

### P1：今日任务健康中心

首页用一处状态回答“今天是否完成、未完成原因、下一步”。例如：尚未到点、电脑未运行、待登录、系统定时未注册、部分失败、待核对；显示最近触发时间、实际开始/结束和下一次检查。提供“检查登录”“查看失败”“去核对”等跳转。

验收：断网不能标为登录失效；系统任务已注册但从未触发时不能标为今日完成；待核对时无自动重发按钮。

### P1：异常提醒与通知设置

提供本机通知开关；按需要支持现有 Webhook/钉钉，再视需求增加飞书模板。默认提醒登录失效、出现待核对、任务明确失败和到指定时间仍未完成；不通知私信正文。通知目标保存后提供测试按钮；失败时显示失败原因且不影响发送结果。

验收：重复检查同一异常不刷屏；网络失败、系统通知无权限、Webhook 不可用各有状态；各账号结果正确归属。

### P1：好友绑定与改名保护

同步后列出候选会话、同名冲突和绑定状态；识别信息不足时保持未确认。分离项目内部 ID、用户备注、搜索名称和可验证的远端会话 ID，逐步迁移旧记录。对当天已发送的好友改名或改文案后仍避免重复。

验收：同名候选、好友改名、页面未提供 ID、会话不匹配、中途切换会话都要测试。真实网页对 ID 的支持是前置研究，不保证可获得。

### P2：火花状态与提醒

研究聊天列表是否可靠暴露火花标志/天数及其含义；仅在可验证时读取并标记“抖音页面读取，更新时间”。如读取不到显示“未知”；不能用本项目发送成功次数伪装成火花天数。支持用户自主选择需要提醒的好友；提醒阈值和火花规则须先实测。

验收：页面未展示、格式变化、数据过期、读到未知状态时不显示虚假数字；同步聊天列表不读取消息正文。

### P2：规则与便利性

按星期选择已有文案池、假期暂停/指定恢复、好友分组批量调整、导入导出配置。与现有节日覆盖、随机/轮换、当天已经准备的内容冲突时，需要预览实际生效规则并优先保护当日去重。

不重新提出已明确取消的 AI 文案与视频回复。账号独立定时、多成员与云端部署属于更大范围，先不纳入第一批。

## 实施顺序与验收门槛

1. **历史保全**：去除写入 30 条截断，提供分页检索和迁移备份。先用临时数据验证，再处理已有历史；不得触碰真实发送。
2. **健康中心 + 通知**：复用已有健康分类；清楚区分配置、系统任务、实际执行和发送结果。
3. **身份绑定预研**：离线模拟 DOM + 用户授权下的只读网页检查；可靠性不足时只交付冲突提示，不强行发布身份绑定。
4. **火花状态预研**：只读、只展示可证实的数据，并处理不可读取。
5. **便利功能**：按实际需求选择按星期/分组/备份。

研究与验证不向好友发送真实消息；真实端到端发送应单独选择用户明确授权的测试对象和时间。新版本发布前覆盖 macOS、Windows、Linux 的定时与唤醒差异。
