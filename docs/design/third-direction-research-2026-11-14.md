# 第三套重做：调研与首页构图

日期：2026-11-14。奶油紫方向已由用户明确否定；暖白橙色与石墨青绿保留。本轮只交付新的第三套桌面首页预览。

## 本轮扩展查阅

查阅官方产品展示与说明，未登录外部产品。网页中的功能说明与实际截图分别判断，不将营销页面直接当作工具界面的模板。

| 来源 | 观察重点 | 本项目采用或舍弃的原则 |
| --- | --- | --- |
| [Todoist](https://www.todoist.com/) | 今日任务入口、简洁条目、辅助信息的位置 | 用任务完成情况组织首页；不引入项目管理功能 |
| [TickTick](https://www.ticktick.com/) | 日程视图与内容的空间关系、列表与时间的区分 | 名单和时间采用不同的信息表达；不引入完整日历 |
| [Sunsama](https://www.sunsama.com/) | 官方首页展示中的左导航、中央任务列、右日程区 | 作为“导航—今日工作—时间上下文”的结构参考 |
| [Superhuman](https://superhuman.com/mail) | Split Inbox 将需要注意的信息集中到对应区域 | 借鉴内容优先级；不加入收件箱或 AI 功能 |
| [Shortwave](https://www.shortwave.com/) | 信息分类、操作与当前内容的关系 | 操作靠近所属内容；不加入其自动化助手 |
| [Craft](https://www.craft.do/) | 文档、任务和日历各有自己的工作区域 | 减少容器装饰，使正文、列表成为主体 |
| [Amie](https://amie.so/) | 当前公开产品展示及任务文档 | 当前首页已突出会议与 AI，不沿用旧日历产品印象作为当前事实 |
| [Amie Tasks](https://amie.so/documentation/features/tasks) | 日历和任务在同一视图中的关系 | 时间信息作为任务上下文，不增加新的任务属性 |
| [Akiflow](https://akiflow.com/features) | 捕获、整理、执行任务的分工 | 常用动作入口清楚；不搬入复杂时间管理功能 |
| [Akiflow calendar](https://product.akiflow.com/help/articles/0807758-customize-your-calendar) | 布局密度与任务列/日历列关系 | 密度由内容决定，不为填满屏幕添加卡片 |
| [Linear redesign](https://linear.app/now/how-we-redesigned-the-linear-ui) | 环境、外观与层级的分别验证，导航对齐与多种视图 | 重做结构时也检查账户、列表、动作的归属；不只更换主题色 |

## 视觉核查与边界

另打开了 Todoist、TickTick 的官方图像核查：选中的 Todoist 图片实际是移动端展示，因此只取其内容层级，不用于本次桌面布局；TickTick 图像包含桌面月历与移动端，不复制月历，只观察对齐、行列和色彩的克制使用。Sunsama 的官方图片说明可确认分区结构；浏览器加载与部分原图访问超时，不声称已完整实测这些界面。

## 新第三套：瓷白朱红

设计判断，不是来源的事实描述：

- 减少导航面积，使用带文字的窄导航；账户始终清楚可见。
- 白色与极浅中性灰建立空间关系，墨黑文字；朱红只作为识别、选择和少量操作强调，绿色仅表达成功。
- 中央工作区直接显示今日结果和精简好友名单，右侧以时间顺序组织最近运行与下次计划。
- 名单采用两列轻量条目，不再把主区域做成又一张三列表格。
- 标题适度，不用大口号；取消重复完成百分比和多块统计卡；保留立即发送、试运行、好友、任务和记录入口。
- 头像和姓名采用匿名演示数据，图内明确标注；不把真实账户数据上传生成服务。
- 预览不修改 UI 源码，不代表界面实现或功能已完成。

首张图主要判断：窄导航是否清楚，中央与右侧的分工是否好读，瓷白朱红是否形成可用且有辨识度的系统。待用户判断后，再扩展本套其他页面。
